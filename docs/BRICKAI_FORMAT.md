# Brick AI Studio package format

`.brickai` is a ZIP container produced by BrickLayer Mobile for Brick AI Studio structural study. It is not a replacement for `.bricklayers`; it embeds the official `.bricklayers` project plus metadata and standardized 3D views.

Initial training format: `brickai-training-v1`.

## ZIP structure

```text
model.bricklayers
manifest.json
metadata.json
views/front.png
views/back.png
views/left.png
views/right.png
views/top.png
views/bottom.png
views/iso_front_left.png
views/iso_front_right.png
views/iso_back.png
```

Future versions may add folders such as `reference/`, `analysis/`, `sections/`, or `manual/`. Consumers should ignore unknown paths.

## Manifest

`manifest.json` identifies the package files:

```json
{
  "format": "brickai-package",
  "version": 1,
  "model": "model.bricklayers",
  "metadata": "metadata.json",
  "views": {
    "front": "views/front.png",
    "back": "views/back.png",
    "left": "views/left.png",
    "right": "views/right.png",
    "top": "views/top.png",
    "bottom": "views/bottom.png",
    "isoFrontLeft": "views/iso_front_left.png",
    "isoFrontRight": "views/iso_front_right.png",
    "isoBack": "views/iso_back.png"
  }
}
```

## Embedded model

`model.bricklayers` is a complete `bricklayers-v1` JSON export generated by the same serializer used by `Guardar .bricklayers`. Its voxel geometry and color codes are the authoritative source.

## Units and dimensions

BrickLayer logical voxels use:

- `X = 7 mm`
- `Y = 7 mm`
- `Z = 5 mm`

`metadata.dimensions.x` and `metadata.dimensions.y` come from the project logical grid. `metadata.dimensions.z` is `max(layer.z) + 1`. Physical size is calculated only from logical dimensions:

- `width = X * 7`
- `depth = Y * 7`
- `height = Z * 5`

## Metadata

`metadata.json` uses this shape:

```json
{
  "format": "brickai-training-v1",
  "generator": "BrickLayer Mobile",
  "modelName": "7299",
  "block": { "x_mm": 7, "y_mm": 7, "z_mm": 5 },
  "dimensions": { "x": 33, "y": 33, "z": 65 },
  "physicalDimensionsMm": { "width": 231, "depth": 231, "height": 325 },
  "voxelCount": 3178,
  "layerCount": 65,
  "paletteCodesUsed": ["N", "B"],
  "colors": [
    { "code": "N", "name": "Negro", "hex": "#111111", "voxelCount": 120 }
  ],
  "layers": [
    { "z": 0, "voxelCount": 31 }
  ],
  "views": []
}
```

Color names and HEX values come only from `palette.js` / `BRICKLAYER_COLORS`.

## Coordinates and orientation

The coordinate system matches the BrickLayer 3D viewer:

- `X`: left/right logical grid axis.
- `Y`: front/back logical grid axis, rendered as scene depth.
- `Z`: vertical layer axis.

Standard view names correspond exactly to the current viewer buttons:

- `front`: `Frente`
- `back`: `Atras`
- `left`: `Izquierda`
- `right`: `Derecha`
- `top`: `Arriba`
- `bottom`: `Abajo`

Isometric views are fixed camera presets:

- `isoFrontLeft`: front + left side + top.
- `isoFrontRight`: front + right side + top.
- `isoBack`: back + side + top.

## Render convention

All PNG views are square `1024 x 1024`. The background is fixed neutral gray `#343941`; user interface backgrounds are ignored.

The capture is offscreen. It renders only the official BrickLayer 3D brick geometry and materials: body, top stud, and bottom socket proportions from `viewer3d-model.js`. It does not render UI, axes, text, references, selection highlights, recolor overlays, or layer filters.

The camera is normalized per view: the full model bounds are centered at the origin, projected against the fixed camera direction, and fitted with a small constant margin. Exporting the same model twice should produce equivalent framing.
